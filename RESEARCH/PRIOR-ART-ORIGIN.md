# Prior art — the mission's own tooling (`tools/origin`)

Written 2026-10-04, session `2026-10-04-045`. Follows the method of
[`PRIOR-ART-KNITTING.md`](PRIOR-ART-KNITTING.md) and the
[`prior-art-check`](.agents/skills/prior-art-check/SKILL.md) skill.

## The question, and why it is asked now

Every candidate this mission has generated by ideation has died to prior art
or to a trivial baseline — F001, F006, F008, F009, F012, plus six rejected in
`RESEARCH/D.md` and `RESEARCH/B.md`. Eleven in a row, none surviving.

`tools/origin` had never been in that count, because it was never treated as a
candidate. It is a **byproduct**: ~9,800 lines of standard-library Python that
appeared because two VMs needed to coordinate, and it has been used 88 times in
two days. Its implied status was "infrastructure, not a candidate."

That status was never tested. This report tests it. The byproduct thesis is
that building what you need as you go lands somewhere ideation does not. If it
is wrong, then the mission has tested **twelve** candidates for **twelve**
prior-art deaths, and the selection procedure itself is the thing that is
broken.

**The honest framing matters for what follows.** A negative result here is not
a wasted session; it is the first time the mission has examined its own most
substantial artifact with the tool it built for examining candidates.

## Method

Three vocabularies, as the skill requires:

1. **The user's vocabulary** — what a developer who hits this problem calls it:
   *agent session log*, *flight recorder*, *black box for AI agents*, *audit
   receipt*.
2. **The infrastructure term** — what a systems engineer calls the mechanism:
   *reconcile a session record against version-control ground truth*,
   *declared-artifact verification*, *provenance attestation*.
3. **The academic term** — `arXiv` full-text search for agent-run provenance
   and reproducibility.

Searches ran through the GitHub REST search API and DuckDuckGo's HTML endpoint,
because the session's `websearch` tool returned `{"error":"Web search
cancelled"}` on every attempt, six times, across three different queries
(2026-10-04). Both direct endpoints returned 200. **This is a weaker instrument
than a general web index**, and the limits section says so.

That is `origin session` plus `tools/x`. It is not a mechanism this mission
invented, and the naming is close enough that a reader would describe both the
same way.

## Finding 2 — the reconciliation half is prior art, directly and recently

This is the load-bearing finding. `origin`'s distinctive claim is that a session
**declares** its artifacts (with sha256) and the tooling then checks that
declaration against git, reporting files the session changed but never declared
as `unlogged_change`.

[`gitreceipts`](https://github.com/jagmeetchawla/gitreceipts) (MIT, Rust,
`jagmeetchawla`) — crates.io, created 2026-07-23, v0.1.5 published 2026-08-10,
**158 total downloads, 2 GitHub stars, 11 open issues**. Its crate description:

> gitreceipts — reconcile a coding-agent session log against the git history it
> claims to explain. The pipeline: ingest (tolerant JSONL) → causal (parentUuid
> order) → extract (claims with receipts) → reconcile (the interval equation
> against the repo's reflog spine) → report (console ledger).

Read from `src/reconcile.rs`'s module documentation (`observed`):

> Real commits are the spine. For each interval A→B, what commit B introduced is
> the bank statement and the session's claimed file mutations are the itemized
> ledger. Green means they balance. Red comes in two flavors: **claims that
> never landed in any statement, and residue — files the statement says changed
> that the log never claimed** (human edits, or command side effects).

**This is a strict superset of `origin`'s check.** `origin` reports one
direction — residue. gitreceipts reports residue *and* the inverse (declared
work that never reached a commit). It also has `Sibling Writes`, a per-repo
count of changes a session made into *sibling repositories* without exposing
their paths, which is the same problem as this repository's landed-work
attribution defect (D028, T-0024) solved independently.

**Conclusion, `observed`:** the mechanism is prior art, six weeks old at the
time of writing, MIT-licensed. F026.

## Finding 3 — the process doctrine was independently reinvented too

This is the part that was not expected, and it is the most decision-relevant.

`KNOWN-LIMITATIONS.md` and `docs/COMPAT.md` in gitreceipts, quoted verbatim
(retrieved 2026-10-04):

> *"loosening the match far enough to cover it would start laundering real
> losses. Read the diagnosis before reading the red as a lie; the errors here
> skew toward false alarms, never toward hiding."*

> *"Numbers are the strongest guarantee: console, HTML, and JSON always carry
> identical values for every headline and exception count… nothing ships while a
> number disagrees — the three surfaces are three renderings of one receipt."*

> *"It REMOVED `exceptions.created_elsewhere`, which measured how far back the
> local reflog reached rather than where a commit came from — the one removal so
> far, made because **keeping a field that cannot mean what its name says is
> worse than the break**."*

Compare the mission's own rules, arrived at over 87 sessions:

| This repository | gitreceipts |
|---|---|
| "Do not weaken an integrity check merely to make a result look successful" (`AGENTS.md`) | "loosening the match… would start laundering real losses" |
| A hand-authored document may not say a thing twice (D043, defect 20; 47 generated reports found repeating a row) | console, HTML and JSON "always carry identical values… the three surfaces are three renderings of one receipt" |
| A record whose header cannot mean what it says is a defect (defect 14, T-0042) | removing a field "that cannot mean what its name says is worse than the break" |
| Gaps are documented with the same care as features (every `FAILURES` entry) | "The tool's honesty is the product, so its gaps are documented with the same care as its features" |

**`observed`: the intellectual content of this mission's discipline was
independently arrived at by one person, in Rust, in three weeks, without any
contact with this repository.** Its README, GitHub description, limitations
page, and compatibility page are all dated 2026-07-23 to 2026-08-11.

The implication is not flattering and it is the point of this report: **process
discipline is commodity. It is not a differentiator, it is not scarce, and a
mission cannot win by having it.**

The same 11 open issues name five gaps. Three map one-to-one onto problems this
repository spent real sessions on:

|---|---|

| **#8** "Cross-machine and mounted-drive audits are not supported… Sessions are keyed by the absolute path they were recorded at" | Two VMs at different absolute paths; the fleet harness (T-0004); `doctor` comparing each VM's versions against the shared record (T-0033) |
| **#5** "On-time landings are verified at path level, not content level" | This repository records **sha256** per artifact (1,085 `artifact` events) — content-level, which is stronger |
| **#4** "Declaring committed build artifacts — 'derived, not authored'" | Declared exemptions for vendored/generated files — which "bit this VM five times in three sessions" |
| **#9** "v0.1 reads Claude Code session logs only" | `origin` is harness-neutral; its events are `origin.session.event/1` |

Two of its issue classes are defect classes this repository found in itself:
#3 ("Export vs rendered view disagreed at 0.1.1 — neither is a wrong displayed
number") is defect 20; #2 (files created by `cp`/`convert`/a script never
become a claim, "all 22 residue entries in one repo") is F022's class.

**The honest reading, `inferred`:** the hard part of this problem is not the
mechanism. It is the operational detail that only bites under real multi-agent,
multi-machine use, and this repository holds two days of documented, tested
evidence about where it bites.

**The honesty that matters more, `untested`:** an issue list in a 2-star project
is one person's known gaps. It is **supply-side absence with no demand-side
evidence whatever**. It is not a market. Nothing here shows anyone else wants
the multi-lane case solved.

  path" cannot discriminate between candidates in a niche where every candidate
  scores zero, so it carries no information here.

## What was not done, and what is therefore unclaimed

- **The baseline was not executed.** The skill requires running the strongest
  alternative, not describing it. `cargo` is absent on this VM (Python 3.8.10,
  2 CPUs, 0.8 GiB free), so gitreceipts could not be installed or run, and the
  head-to-head comparison against `origin` on real session logs is
  **`unperformed`**. No claim is made that `origin` is better or worse at
  reconciliation.
- gitreceipts's ingest reads **Claude Code** JSONL. This repository's logs are
  `origin.session.event/1`, written by a different harness. It therefore could
  not audit this repository's streams even if Rust were installed, unless a
  converter were written. Measured from `src/schema.rs`'s documented types, not
  by running it.
- The arXiv search returned nothing for `"agent session log" AND provenance`.
  That is one query, not an absence of academic prior art.
- GitHub search was restricted to `name` and `description` fields for the API
  queries. Projects that describe themselves differently were not found. Code
  search needs authentication and was not available.

## What this changes

1. **`tools/origin` cannot be presented as novel.** F026. Neither the mechanism
   (Finding 2) nor the discipline (Finding 3) is original. If a public front
   door ever claims otherwise, that claim is false.
2. **The byproduct thesis is disconfirmed in its strong form.** Building what
   you need as you go does not escape the prior-art wall; it lands inside it,
   because the need is a real need that other people have already met.
3. **The mission's candidate selection procedure is now the suspect.** Twelve
   candidates, twelve prior-art deaths, and the twelfth was not even generated as
   a candidate. Prior-art survival cannot be the filter, because nothing this
   mission produces passes it.
4. **What remains genuinely scarce is not process and not code.** It is (a) the
   ability to run disciplined work continuously, and (b) domain knowledge about
   a specific problem. Finding 4 says this repository has (b) for one narrow
   problem and no evidence that anyone wants it.

## Reconsider when

Any of: a real user asks for agent-run auditing; gitreceipts gains a
multi-lane or cross-machine mode (issues #10, #8 closed), which would erase
this repository's only measured advantage; or a candidate arrives whose
*domain* content, rather than its process, is the thing being defended.
