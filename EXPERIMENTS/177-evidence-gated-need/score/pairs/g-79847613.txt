The rule exists because a virtual function's identity must not depend on template argument
s: for a given dynamic type, the vtable must have an entry for every function the base dec
lares. If a derived class could constrain its override, the override would silently vanish
 for some instantiations while calls through Base* still had to dispatch, so the call woul
d reach a base function with a different contract, and final-overrider lookup breaks. It a
lso breaks template argument deduction. The supported pattern is the one you found: constr
ain the class template (partial specialization, or a requires clause on the class), or pro
vide unconditional overloads that delegate with if constexpr, or use CRTP so dispatch neve
r relies on the virtual table.

 I would say that the rationale is to avoid having to decide whether different requires hi

 Imagine valid code: 
 template <int I>
concept isEven = ((I % 2) == 0);

template <int I>
struct Base {

 void f() requires (isEven<I>) { std::cout << "even\n"; }
 void f() requires (isEven<I> && I == 0) { std::cout << "0\n"; }
 void f() requires (I == 1) { std::cout << "1\n"; }
};
