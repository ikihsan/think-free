 The attributes are hints to the compiler for optimization. There are two main things that
 the compiler can do with this: 
 
 It can arrange the code so that the branch predictor's default choice (i.e. what to do if
 there's no history for the branch) takes the likely path. The common heuristic you hear a
bout is that backwards branches (target instruction is earlier than branch instruction) ar
e assumed to be taken (they look like loops, which are typically repeated more often than 
ended) and forward branches are assumed to not be taken. 
 
 It can put unlikely code far away from the likely code in a process called "outlining", s
o that the instructions that are unlikely to be executed anyway don't take up space in the
 instruction cache.
