=== LEFT ===
Your find directive is wrong: config is itself a package directory, not a folder containin
g packages, and where must list roots. Use a flat layout where the project root holds the 
packages, for example [tool.setuptools.packages.find] where = ['.'] include = ['config*','
packages*'] with a matching package-dir, or a src layout where = ['packages/src'] and move
 config under packages/src. Also note that a top-level module named config is a bad global
 name likely to collide with other packages. A cleaner option is hatchling with [tool.hatc
h.build.targets.wheel] packages = ['config','packages/src'], or a single src/ layout, and 
renaming config to yourapp.config. Finally, uv pip install -e . only helps if you run the 
script with that interpreter.

# -*- coding: utf-8 -*-

from dashboard.services.data_ingestion import main
if __name__ == "__main__":
 if sys.argv[0].endswith("-script.pyw"):
 sys.argv[0] = sys.argv[0][:-11]
 elif sys.argv[0].endswith(".exe"):
 sys.argv[0] = sys.argv[0][:-4]
 sys.exit(main())
 
 Since ~/.venv/bin is added to your PATH variable when you installed uv (by using the glob
al script, not by pip install uv or within a virtual environment), you can call the CLI co
mmand from everywhere after the install!

Although for this, you have to make some entries into the __init__.py files—some imports—t
o manipulate the final composition of the namespace (e.g., you don't want certain file nam
