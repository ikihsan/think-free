=== TITLE ===

=== QUESTION ===
Here's the test code:

template<typename T>
concept Printable = requires(T obj) {
 { obj.print() } -> std::same_as<void>;
};

template<Printable T>
void func(const T& obj)
{
 obj.print();
}

class Foo

 void print() const { /* std::cout << "Foo" << std::endl; */ }

=== KEY ANSWER ===
A concept is a named constraint. Your concept is 
 template<typename T>
concept Printable = requires(T obj) {
 { obj.print() } -> std::same_as<void>;
};
 
 So Printable means that obj.print() can be called. Since print() is private in your examp
le and you expose it via another method, it seems to be a bug, as the expectation is to be
 able to call the print() method directly and you cannot do an obj.print() .
