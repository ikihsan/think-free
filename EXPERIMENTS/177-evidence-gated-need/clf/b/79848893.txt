=== TITLE ===
The call is ambiguous between identical methods

=== QUESTION ===
I am in the process of upgrading our codebase from .NET 9 to .NET 10. All of the libraries
 of all of our packages were upgraded to the most recent version when I last upgraded to .
NET 9. 
 I did the same thing this go around and brought everything up to the most recent code ver
sions. 
 I have not done any code changes whatsoever and all of this code compiled and ran before 
the version update. 
 However, I am stuck on this error, and it doesn't make any sense to me. 
The two methods it is referring to are identical. 
 
 The call is ambiguous between the following methods or properties 
 System.Linq.AsyncEnumerable.ToListAsync(System.Collections.Generic.IAsyncEnumerable, Syst
em.Threading.CancellationToken) 
 and 
 System.Linq.AsyncEnumerable.ToListAsync(System.Collections.Generic.IAsyncEnumerable, Syst
em.Threading.CancellationToken) 
 
 I am also getting this with a few other System.Linq functions such as: 
 
 The call is ambiguous between the following methods or properties: 
 System.Linq.AsyncEnumerable.Select<TSource, TResult>(System.Collections.Generic.IAsyncEnu
merable, System.Func<TSource, TResult>) 
 and 
 System.Linq.AsyncEnumerable.Select<TSource, TResult>(System.Collections.Generic.IAsyncEnu
merable, System.Func<TSource, TResult>) 
 
 I have looked at other solutions, such as cleaning out every bin and obj folder in the en
tire project (which I've done numerous times), check for duplicate dll files, etc. and not
hing seems to resolve this. 
 Any help would be appreciated.

=== KEY ANSWER ===
CouchbaseNetClient 3.8.1 references System.Linq.Async (v6.0.1, which is around 3 years old
). Via dotnet nuget why : 
 
 This version exposes the ToListAsync method. .NET 10 has the same method included in the 
framework . 
 Since you have transient dependency on the package you can install it's 7th version which
 seems to have the ambiguity resolved for .NET 10. as stated in the Recommended action sec
tion of the linked before doc: 
 
 If you're upgrading to .NET 10 and your code includes a direct package reference to Syste
m.Linq.Async, remove that package reference or upgrade to version 7.0.0. 
 
 Or for transient dependency (as in your case) you can reference it directly and add <Excl
udeAssets> metadata with a value of compile or all : 
 
 This configuration prevents direct usage in your code while allowing other packages to co
ntinue using System.Linq.Async internally: 
 
 <PackageReference Include="System.Linq.Async" Version="6.0.1">
 <ExcludeAssets>compile</ExcludeAssets>
</PackageReference>
 
 
 Use this configuration only if you're certain no dependencies require System.Linq.Async a
t runtime. 
 
 <PackageReference Include="System.Linq.Async" Version="6.0.1">
 <ExcludeAssets>all</ExcludeAssets>
</PackageReference>
