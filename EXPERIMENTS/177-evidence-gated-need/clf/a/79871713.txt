=== KEY ANSWER ===
In my case, I was getting the same warning and animation glitch when a Menu was inside a G
lassEffectContainer with .buttonStyle(.glass) and . glassEffectUnion() . 
 Adding .compositingGroup() before the button style fixed it: 
 Menu {
 // menu content...
} label: {
 Image(systemName: "ellipsis")
}
.compositingGroup() // fixes _UIReparentingView warning
.buttonStyle(.glass)
 
 The .compositingGroup() creates a rendering boundary that isolates the Menu from parent e
ffects, preventing the UIKit view hierarchy conflict when the menu presents. 
 Even if you're not using glass effects, .compositingGroup() on its own might still resolv
e your issue since it seems to be a general SwiftUI/Menu bug in iOS 26 related to how Menu
 's UIKit presentation interacts with the view hierarchy.
