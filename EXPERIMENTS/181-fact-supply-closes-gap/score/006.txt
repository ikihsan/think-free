PROPOSED ANSWER:
Being on 26.3 does not change the cause, only the fact that no fix has landed. The container is inserted by UIKit when a text field has both a custom inputAccessoryView and a custom inputView, and in iOS 26 it is drawn with the new Liquid Glass material. So no public API removes it, and hidesSharedBackground is not it - that flag affects the bar item's shared background, not the container. Fix it by dropping UIToolbar as the accessory: make inputAccessoryView a plain UIView with backgroundColor .clear or .systemBackground, put your own Done button inside it, and lay it out yourself; keep the picker as inputView. Worth knowing this is now fixed nowhere through 26.3, so it is not a beta that will clear on its own - the report is already filed with Apple, so the remaining action is the workaround.
