PROPOSED ANSWER:
Two things from this thread. First, the behaviour you are seeing is a beta regression - inherited tint for a custom view is documented as unreliable and iOS 26 overrides it more aggressively, so keep the Feedback Assistant reports going. Second, there is still a supported API: only a prominent UIBarButtonItem tints, and to tint a glass UIButton you need the prominentGlass or prominentClearGlass configuration, not plain or glass, with a clear background and the image tinted via withTintColor(.alwaysTemplate) while the bar button otherwise controls the tint. A prominent bar item tints its whole background, which is not what you asked for here. Expect some of this to work only on a physical device on the newest beta, so verify there. Set colours directly rather than relying on inheritance, and do not use UIBarButtonItem(tintColor:) to reach a custom view.

It is a really frustrating situation and here is what has worked for me: 
 
 `baseForegroundColor` and `imageColorTransformer` works only if `UIButton.Configuration` is `.clearGlass` or `.prominentClearGlass` 
 
 
 THIS WORKS FOR ALL STYLES as stated in mhammad's answer 
 `withTintColor` and `withRenderingMode(.alwaysOriginal)` 
 `config.image = UIImage(systemName: "star")?.withTintColor(.magenta) .withRenderingMode(.alwaysOriginal)
` 
 
 
 THIS ALSO WORKS FOR ALL STYLES take a snapshot of your custom view (UIGraphicsImageRenderer) and use `UIBarButtonItem(image: snapshot-of-custom-view)` or set `self.image = snapshot-of-custom-view` property if you are using custom class with a `tintColor` for `UIBarButtonItem` . 
 `final class BarButtonItem: UIBarButtonItem {
// ...
 init() {
 self.image = UIGraphicsImageRenderer(size: button.intrinsicContentSize).image { [weak button] c in
 button?.layer.render(in: c.cgContext)
 }
 tintColor = .systemOrange
 }
}
`
