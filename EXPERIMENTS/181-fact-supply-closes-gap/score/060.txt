That is the missing piece. Because uv came from the curl installer, it resolves against its own managed state and the standalone CPython builds it downloads, and the flag you passed was satisfied by the interpreter it found first - your system 3.13.2 - rather than by fetching the pin. Do it in two steps so there is nothing to resolve: uv python install 3.9.21, confirm with uv python list that 3.9.21 is present, then uv init --package --python 3.9.21 sandbox. Alternatively set requires-python = "==3.9.21" in pyproject.toml and run uv sync. Delete any .python-version file that still says 3.13.2, because that file outranks the flag. Keeping the curl install and a pip install of uv on the same machine is a common source of confusion, so settle on one.
