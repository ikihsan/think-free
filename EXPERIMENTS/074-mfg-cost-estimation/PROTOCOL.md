## 1. Claim (one sentence, scoped)

Given a STEP file of a small metal part (≤ 300 mm envelope, machined/folded aluminum/steel/plastic), a **feature-based** cost estimation pipeline that extracts machining operations (pockets, holes, bends, threads) and applies parametric cost models can predict total prototype-run cost within **±20% MAPE** of actual manufacturer quotes, with **correlation ≥ 0.7**, and does so more consistently than a volume-based heuristic baseline.

## 2. Strongest Baseline (named, not strawman)

**Baseline A (Volume Heuristic):** Cost = material_volume × material_rate + fixed_setup. Material rates from published stock prices. No feature recognition.

**Baseline B (Eyeball Simulation):** A human estimator (author) given only the STEP file rendering and part envelope, producing a quote in ≤ 5 minutes per part — simulating the "eyeball" process practitioners describe.

**Incumbent Commercial:** aPriori, Costimator, Paperless Parts — acknowledged as existing but **not executed here** (license cost, proprietary). Comparison labeled **unperformed**.

## 3. Kill Gate (exact, numeric, predeclared)

| Metric | Threshold | Outcome if missed |
|--------|-----------|-------------------|
| MAPE on held-out test parts (n ≥ 10) | ≤ 20% | **FALSIFIED** — claim abandoned |
| Pearson r vs actual quotes | ≥ 0.70 | **FALSIFIED** — claim abandoned |
| Baseline A MAPE | Must be > pipeline MAPE by ≥ 5 pp | If not, pipeline adds no value |
| Coverage (parts where pipeline produces estimate) | ≥ 90% | If < 90%, abstention rate too high |

**Resource limits:** Stdlib-only Python, no CAD kernel, synthetic fixtures only, ≤ 2 hours wall time for full run.

## 4. Inputs, Oracle, Synthetic Fixtures

### Input Representation
- **Primary:** STEP AP203/AP214 files (text, stdlib-parsable subset)
- **Fallback:** Simplified JSON fixtures encoding: part envelope, feature list (pockets, holes, bends, threads), material, stock dimensions

### Oracle (Ground Truth)
Synthetic cost model with known parameters:
```
total_cost = material_cost + setup_cost + machining_cost + bending_cost + threading_cost
material_cost = stock_volume × density × material_rate
setup_cost = base_setup + Σ(feature_setup)
machining_cost = Σ(tool_path_length / feed_rate × machine_rate)
bending_cost = bend_count × bend_rate
threading_cost = thread_count × thread_rate
```
Parameters calibrated to public job-shop rate cards (e.g., $75-150/hr machine time, $50-100 setup).

**Fixtures:** 30 synthetic parts (10 train, 10 validation, 10 test) generated by `generate_fixtures.py` with known ground-truth costs. Fixtures span:
- Simple plates with holes (2-5 features)
- Enclosures with pockets and bends (5-15 features)
- Mounting plates with threads and counterbores (5-12 features)
- Material: 6061 aluminum, 304 stainless, mild steel, ABS plastic

### Information-Sufficiency Test (pre-implementation)
Two parts with **identical STEP geometry** but **different costs**:
1. Same external envelope, one solid block vs one with deep internal pockets → same STEP boundary representation, different machining time
2. Same geometry, different material (Al vs SS) → STEP may not encode material
3. Same features, different tolerance specs → STEP PMI may or may not be present

**Resolution:** Pipeline must either (a) require material/tolerance as side inputs, (b) abstain when ambiguous, or (c) narrow claim to "geometry-only estimation for fixed material/tolerance class."

## 5. Negative Controls (must fail)

| Control | Expected Outcome |
|---------|------------------|
| Random feature weights | MAPE > 50% |
| Volume-only model on parts where features dominate cost (e.g., many small holes) | MAPE > 30% |
| Pipeline with feature extraction disabled | Reduces to Baseline A |
| Shuffled fixture labels | Correlation ≈ 0 |

## 6. Ablation / Self-Beating

Run pipeline with each component removed:
- No feature extraction (volume only)
- No parametric cost model (ML regression on features only)
- No material side input (assumes aluminum)

Each ablation must perform **strictly worse** than full pipeline on validation set.

## 7. Procedure

1. `generate_fixtures.py` → writes `fixtures/train.jsonl`, `val.jsonl`, `test.jsonl` with ground truth
2. `extract_features.py` → reads STEP/JSON, emits feature vectors
3. `cost_model.py` → parametric cost computation from features + side inputs
4. `evaluate.py` → computes MAPE, r, coverage on each split; runs baselines and controls
5. `report.py` → emits `results.json` with all metrics, per-part breakdown, gate verdicts

## 8. Acceptance Criteria (honest)

- All negative controls fail as expected
- Ablations show each component contributes
- Kill gate thresholds met on **test split only** (validation used for tuning)
- Results reproducible: fixed seed, recorded versions, `results.json` commits

## 9. Scope Exclusions (what this does NOT claim)

- Production-volume pricing (amortized tooling)
- Multi-part assemblies
- Surface finish / heat treatment / coating costs
- Supplier-specific capabilities or capacity
- Real-time quoting integration

## 10. Decision Rule

If kill gate **met**: Document as `inferred` — synthetic validation only; real-world demand and adoption untested. Propose next step: pilot with 1-2 willing job shops.

If kill gate **missed**: Record as `FAILURES.md` entry; abandon feature-based approach; document what geometry information is actually sufficient/insufficient.
